# Isotope Wiring

**Publication status: development-only.** This application is not the website's hosted legacy iframe or standalone editor. Its local build is not publication acceptance. See the [public application/Morse status guide](../../website/experiments/typed-wiring-development.md) and `config/typed-editor-publication.v1.json` at the repository root. Existing PWA, model/convention and broader browser requirements remain in force; this disposition does not remove or replace them.

A Vue/Pinia authored-diagram inspection and alternating-route slice, not the finished replacement application. Binding scope and unresolved domain requirements are in `REQUIREMENTS.md`. The development-server failure and its proposed corrective/preventive actions are tracked in [CORRECTIVE-ACTION-PLAN.md](CORRECTIVE-ACTION-PLAN.md).

## Run

From this directory:

```sh
pnpm install --ignore-workspace --frozen-lockfile --strict-peer-dependencies
pnpm --dir tooling/vue-check install --ignore-workspace --frozen-lockfile --strict-peer-dependencies
pnpm check:local
pnpm dev
```

Ne-20 is visible immediately on opening the app, with edge 8 selected. Leave **First turn: Left** selected and click **Start**. A marker moves along each edge; the path readout grows as it enters edges. **Pause/Resume** controls playback. The path begins **8 → 12 → 10 → 3 → 7**. Use **Start edge** to select without editing. Clicking a colored edge or its label alternates a color change with a direction reversal, independently per edge, without changing the selected start edge. **Clear path** resets the readout. Synthetic crossing/coincident-vertex examples remain test fixtures, not app controls. The records panel, disclaimers and explanatory paragraphs have been removed.

`pnpm build` creates `dist/`; `pnpm preview` serves it. Both Vite servers bind to loopback. Colored-edge edits and each edge's next click operation are saved in this browser's local storage for this origin. They survive reloads and isotope navigation; they do not modify repository files or sync between browsers. No project-file workflow is introduced. The route is computed synchronously, then played at 800 ms per edge. Playback follows authored polylines and arrow direction, highlights completed edges, and reports the stopping reason at the end. Its clock is disposed with the view; animation never chooses connectivity.

## What remains

- `src/schemas/`: authored graph/layout/document validation, optional basic isotope facts and citations, inspection selection, unresolved or explicit alternating policy, and the actual computed trace.
- `src/examples/neon20.ts`: newly authored Ne-20 diagram, with explicit stable IDs/endpoints and labels 1–27 except retired duplicate 5. `diagrams.ts` is the single registry for availability, construction and initial edge selection. `synthetic.ts` remains a test fixture.
- `src/domain/route.ts`: ID-based incidence and exact rational/BigInt authored-plane turn classification, independent of Vue, DOM, screen coordinates, CSS palettes and drawing order. Authored red/blue/green classes now govern traversal eligibility.
- `src/presentation/diagram.ts`: pure ID-based projection. Direction arrows use authored direction; midpoint labels use half the authored polyline length. Floating-point projection never changes exact source coordinates or establishes connectivity.
- `src/vue/`: full-height application shell, dockable isotope catalog, diagram/playback view and pinned reference graphs. `DiagramGlyphs.vue` shares edges, vertices, arrows and labels between active and reference views. The diagram store owns the active document/playback; the catalog store owns UI choices, navigation and explicit pinned snapshots. Both expose readonly state.
- The start-edge selector keeps obscured edges selectable; vertices can be selected on the diagram. Overlapping labels are not merged or offset; visual overlap resolution is not claimed complete.

The newly authorized narrow edge-click persistence is implemented with schema-validated per-edge overrides, using native URLSearchParams as the text codec. Endpoints, geometry, IDs and labels cannot be edited. Green/unresolved edges remain selection-only. Successful edits stop and clear the computed route without changing pinned snapshots or camera framing. Save failures leave the model unchanged and display an error; unreadable/incompatible saved data disables editing without overwriting it. Sequential stale-tab saves are rejected; this is not a cross-tab transaction system. Browser data clearing removes these local edits. Red and blue counts are checked independently of traversal: unequal counts show an immediate warning. Draft editing and diagnostic playback remain available, but an unbalanced full traversal returns `invalid-color-balance`, never `completed`. Current base counts are 9 red / 7 blue; they have not been silently corrected.

Speculative general save/edit/workspace/session protocols, project containers, attestations/attachments, tool-version records and PWA protocols have been removed. File import/export/recovery is excluded. No replacement abstraction for those features is planned. PWA remains unimplemented. Alternating traversal now has a concrete minimal implementation, not a general workflow framework.

## Morse surface

Open **Morse** for a read-only surface construction from the active wiring. With the authored Ne-20 clockwise attachments, it has genus 5, six boundary circles, Euler characteristic −14 and 15 independent graph cycles. The Ne-20 view contracts edges 8 and 9 only in the Morse presentation, giving 10 minima and 24 saddles with no interior maxima. It preserves the inherited attachments, including the surviving loop and parallel bands; the original twelve-vertex wiring stays unchanged. The dialog exposes attachment orders, boundary walks and exact critical levels; it also checks the current arrows for directed-cycle obstructions. It does not edit wiring, versions, playback or camera state.

This is a combinatorial surface with a Morse handle realization, not a rendered 3D mesh or a nuclear-physics claim. See [MORSE_SURFACE.md](MORSE_SURFACE.md) for the gluing construction, local function charts, conventions and limitations. Run `pnpm check:morse-surface`; its generated receipt is independently checked by `python research/strominger/checkers/check_ne20_morse_surface.py` from the repository root.

## Named versions

Open **Versions** in the toolbar. Enter a name and choose **Save new**, or select a saved version and **Load** / **Delete**. Names are unique (case-insensitive), with at most 100 versions per diagram. Load and Delete ask for confirmation; saving never overwrites an existing name. The dialog focuses the name field on opening and after saving. Escape, Close or an outside click dismiss it without editing the graph. Loading closes it and focuses the graph; deletion leaves focus on an enabled control. The toolbar shows only the Versions button. Inside the dialog, a comparison is shown only when saved versions exist: “Matches saved version(s)” or “Differs from saved versions”. This is a content comparison, not an unsaved-edits warning, and retains its meaning after browser reload. Long names wrap; multiple matches use a bounded count summary. The empty-state message is brief, and detailed storage information is collapsed under “What is saved?”. Feedback stays above the scrollable controls, including on short screens.

Versions persist in this browser/origin and contain every colored edge's color, arrow direction and next click operation, plus the selected start edge and first turn. They are snapshots, not live aliases: editing a loaded version does not change its saved copy. Unbalanced drafts can be saved, retaining their validation warning. Loading atomically persists the restored active edits and start/turn settings, clears playback and preserves camera framing and pinned graphs. The active settings survive refresh without loading the named version again. The chooser is not an active-version indicator and starts unselected after browser reload. Opening refreshes the list and clears old operation feedback; storage events update it when another same-origin browsing context changes the library. Save is disabled with an explanation when the library cannot be read or has reached 100 versions. The diagram title and current comparison status are visible inside the dialog. Deleting a version does not change the active diagram.

Versions are not project files, browser-sync or a routing-rule history. Loads use current routing rules. Changed topology/geometry is rejected without deleting the saved version. Named snapshots bypass live-edit color migrations. Storage failures and corrupt libraries are reported without overwriting existing data. Browser data clearing removes this local library as well as active edits.

`pnpm check:named-versions` covers capture/restore, exact encoding, compatibility and failed/stale writes. Browser checks additionally exercise save/load/delete across browser restarts, duplicate names, confirmation cancellation, storage failure, restored controls/click phase and subsequent edits. A separate refresh stage verifies the active settings before any Load action; native pointer/typing checks exercise real Save clicks and browser confirmation dialogs, focus return, Escape and outside dismissal over a colored edge, and reachable controls/feedback at 320×360 in both empty and populated states, including long names. Additional browser stages cover capacity and recovery, real same-origin storage events, stale feedback, refresh-on-open and modified-state meaning after restart.

Empty overlay space passes pointer input through; controls and scrollable readouts remain interactive.

Implemented from the legacy UI: full-height shell and compact toolbar; isotope panel with dock/undock and close/reopen; search, element and mass filters; back/forward navigation; pin/unpin reference graphs alongside the active graph; counts toggle. Start-edge, first-turn and speed selectors operate the new routing/playback. The playback button starts, pauses, resumes, or restarts a completed run. Steppers pause playback and move to the previous/next segment boundary; forward can initialize a route, back cannot. Boundary buttons are disabled at the start/end. Zoom ± and cursor-anchored wheel zoom span 0.25×–8×; **Fit** restores the authored framing. **Move** enables pointer dragging and arrow-key panning when the graph is focused. Escape leaves Move; +/− zoom and F fits. Camera state is presentation-only and resets on a document switch. Modified browser shortcuts are left alone; wheel delta units are normalized. Capture is released on drag termination, mode exit and component disposal; cancelled drags cannot select edges on mouse-up. Pins and choices remain in memory only.

The catalog is a frozen snapshot of the 96 names and proton/neutron counts from `research/matter/isotope-reference.resource.json`. `check:catalog` checks every snapshot row against the canonical resource using the pinned compiler's JSON parser. Catalog result collections are readonly; filters and presentation toggles preserve active and pinned document identities. All **17 catalog entries before Neon-20**, plus Neon-20 itself, have authored replacement diagrams. The other 78 selections show **Diagram not yet available**, stop playback and preserve pinned references. No legacy graph extraction or placeholder Ne-20 graph is used for another isotope.

The H/He models in `src/examples/light-isotopes.ts` now have authored red/blue arrows and the current alternating policy, replacing the non-editable green drafts. The legacy H/He source supplies shapes, not those arrow choices. `src/examples/pre-neon-isotopes.ts` adds Li-6 through F-19 from the named Li-6-based drawing recipes, with explicit endpoint identities, reflections, wrapper endpoints and bends. Shared schema/assembly lives in `src/examples/authored-isotope.ts`; no SVG extraction or inventory-to-geometry generator is used. Green connectors are undirected under the current convention. Electronic state and charge remain unspecified. See [PRE_NEON_DIAGRAMS.md](PRE_NEON_DIAGRAMS.md) for the reference map and authoring distinctions. `check:diagrams` covers all 17 models, editing/restoration, activation, pins, Morse construction and non-junction crossings; browser checks exercise selection, arrows, labels, color/direction clicks and reference isolation for every model. Catalog coverage is not a count of existing legacy drawings: the empirical reference has 96 entries, while the old app has a separate collection of named drawings, including isotopes outside that reference. The remaining 78 entries therefore require source review and, where necessary, new authoring rather than an assumed mechanical migration.

This is the first UI carry-over, not full legacy parity. Other isotope diagrams, reference-observation settings and remaining display options are still outstanding. Removed project-file and records-dump controls remain removed; edge clicks are the explicitly authorized editing surface.

### Compiler ownership and enforcement

- TypeScript **7.0.2** checks domain/presentation/configuration and verification helpers.
- The approved separate **TypeScript 6.0.3** project checks SFCs and Vue-coupled TypeScript under `src/vue/`. Its lockfile pins vue-tsc and Vue language-core **3.3.14**, Volar **2.4.30**, Vue compilers **3.5.44**.
- vue-tsc's compiler dependency is incompatible with TypeScript 7; the explicitly approved sidecar avoids a forced peer override. No ambient `*.vue` shim is used.
- `scripts/type-audit.ts` uses the pinned TS7 `typescript/unstable/*` API. `tooling/vue-check/audit.ts` uses real Volar service scripts/source mappings. Both reject unsafe authored values, suppressions and unchecked schema constructors; independent coverage catches excluded helpers/components and unchecked JavaScript/declarations.
- Framework metadata is not recursively treated as owned data, but actual unsafe member reads fail. Positive controls prevent a reject-everything checker from passing.
- Ox syntax linting runs everywhere; native type-aware Ox checking covers native-owned code; the full Vue checker/auditor is mandatory for Vue-owned code because Ox cannot resolve SFC types itself.
- The no-emit Vue project permits `.ts` imports and disables import-extension rewriting to avoid TS2876 on `.vue` paths. Native verification emission retains rewriting. Strictness is unchanged.
- Existing enforcement coverage: **24 native**, **30 Vue**, **2 configuration**, **9 coverage/ownership** cases. No compiler API stability beyond these pins/probes is claimed. Upgrade failures must block checking, not disable it.

## Authored Ne-20 and routing choices

The operator clarified that the new model/labels are ours to create and that 10 → 3 follows alternating left/right. No screenshot or existing identity table is required. The new model has 12 explicitly named vertices and 26 edges: 16 directed red/blue edges and ten undirected green segments (6, 7, 12, 17, 22–27). Green segments have no arrowheads and can be traversed from either endpoint. Labels are authored constants, not DOM indices. Edges 17/22 are vertical. In shell 2, NW–SE sides point SE and SW–NE sides point NE. Their colors are red and blue respectively, except the latest color-only overrides: **13 and 14 blue; 16 and 20 red**. Existing v1 saved overrides receive this approved swap once, retaining arrows and next-operation state; v2 saves respect subsequent UI edits. Their latest directions are **13: bottom-right → bottom-tip** and **14: bottom-left → bottom-tip**. Latest overrides: **2 blue, center → middle-right**; **4 red, center → bottom-right**; **15 red, bottom-left → left-tip**. These supersede the prior colors and directions of 2/4. Red **19** is also reversed to **right tip → middle-right**, permitting **26 → 19**. Shell 1 and all horizontal/vertical green segments are unchanged. Shell 2 has both diagonals in each of its four diamonds: 23 joins top-junction to center, 24 center to bottom-tip, 25 left-tip to center, and 26 center to right-tip. Crossings with 7, 6, 17 and 22 respectively do not create junctions. Top-shell vertical green 27 joins upper-tip to top-junction, crossing 12 without a junction; no existing IDs or saved overrides are changed. Basic isotope facts are Z=10, N=10; the diagram is not claimed to be a validated physical nuclear structure.

At the top junction, edge 10 arrives from the upper-right vertex. Edge 3 leaves toward the middle-right vertex (left turn relative to arrival); edge 1 goes toward the middle-left vertex (straight). The same rule used everywhere selects 3—there is no 10-specific branch in the engine.

Concrete implementation proposals beyond the confirmed alternation rule:

- Default left first, with an explicit right-first control; starts follow the authored arrow.
- Left/right uses exact terminal tangents in the authored y-down plane. Model IDs alone establish incidence. Intermediate points affect tangents but cannot create junctions.
- **Keep left / keep right** selects the leftmost/rightmost available non-reversing exit, using exact authored tangent cross-products. After own-color priority, remaining eligible exits share one signed angular order. Comparison never reverses when exits lie on the opposite side; there is no separate opposite-side fallback. Distinct angles are ordered, not treated as ambiguous. No edge-specific continuation table or isotope special case exists.
- Straight travel preserves the pending side; a turn alternates it. Distinct edges sharing the same extreme ray are a genuine tie; zero tangents stop rather than guessing. No eligible exit stops the trace, as does a repeated edge/direction/pending-turn/active-color/visited-colored-set state.
- Existing IDs 5 and 18 are retained independently. The shell-2 orientation rule now makes both blue NE channels from bottom-left to center, so they are a genuine same-ray tie rather than opposite channels. They are not silently merged; both remain selectable.

The operator confirmed keep-left/keep-right selection and undirected green segments. Policy v14 enforces strict visit-once traversal for red and blue edges. The first colored edge establishes the active color; green connectors may be reused and do not change it. The other color remains blocked until every edge of the active color has been visited. At that point it immediately becomes the own color and the pending left/right preference flips, together before exit selection. This transition flips the preference exactly once: entering the first exit must not immediately flip it back. Ordinary non-straight alternation resumes at the following junction. The balanced operator regression preserves the supplied prefix and then follows 13 → 14 → 6. Own-color priority applies immediately at the handoff as well (13 → 14 rather than green 24 when 14 is eligible blue). The assistant-added first-exit exception is removed; the new phase persists across green travel. Arrow directions are not reversed by a phase change. Eligibility is filtered first. After a green edge, an available straight green continuation has first priority, including over same-color arrows (26 → 25 instead of 21, and 24 → 23). Otherwise, an eligible, unvisited active-color arrow takes priority over green regardless of left/right preference, while obeying its arrowhead. Angular ranking chooses among equally prioritized exits. Straight travel preserves the pending turn; left/right ranking resolves the remaining choices. Finishing all colored edges ends the run; a blocked phase never silently switches colors or reuses a colored edge. The unedited base diagram's current left-first run is **8 → 12 → 10 → 3 → 7 → 21 → 4 → 20 → 19 → 7 → 17 → 15 → 16 → 1 → 11 → 12 → 9 → 27 → 23 → 24**. It exhausts red, then stops at bottom-tip with blues **2, 13, 14 and 18** still unvisited. Browser-saved color/direction overrides can produce different paths. That base trace is blocked. The historical two-pair swap yielded a 30-traversal closed trace under policy v11, but that 9-red/7-blue configuration is invalid and later policy corrections change its trace. A regression still ensures that even a closed traversal covering every colored edge cannot be reported as `completed` when the counts differ. No lookahead, backtracking or new junction has been invented. The general extremal rule chooses 7 over 22, then 21 over 17; neither junction needs an exception. The prior 15 → 6 continuation is superseded by the operator's reversal of 15. The earlier 22 → 2 discrepancy was not resolved by an alternation correction; the latest operator change now makes 2 blue and directed into middle-right, superseding that continuation for the current model. This is not a claim that the broader alternation audit is closed. Other corner-case conventions remain proposals. Tests cover extremal choices, mirror symmetry, genuine same-ray ties, cycles, straight handling, exact rational scaling, array-order invariance, strict colored visits, phase switching, reusable greens and progress-aware loop detection and disconnected coincident vertices.
