# Which isotope editor is hosted? Typed-app and Morse status

**Publication decision: `apps/isotope-wiring/` is development-only.** It is **not the hosted iframe editor**, and this public explanation is not a published application. Its local `dist/`, source commit or private-package flag does not establish website release or application acceptance.

## Morse construction: incidence plus a supplied attachment convention

The source [apps/isotope-wiring/MORSE_SURFACE.md](https://github.com/andrey-kokoev/marici/blob/main/apps/isotope-wiring/MORSE_SURFACE.md) starts with an authored graph of **12 vertices and 26 edges**. Its five non-junction crossings do not create vertices. Take one oriented disk per vertex and one band per edge; clockwise authored outgoing tangents order the attachments, and the bands are untwisted. Colors and arrows do not determine that rotation system.

For that convention the source reports **genus 5**, **six boundary circles**, Euler characteristic **−14** and first Betti number **15**. Its uncontracted handle presentation has **12 minima and 26 saddles**, with **no interior maxima**. These are source-reported combinatorial/handle results, not a numerical mesh or a nuclear surface measurement.

The default Ne-20 Morse presentation contracts **edges 8 and 9** only in the handle description, retaining inherited cyclic attachments and original-vertex provenance. It has **10 minima and 24 saddles**, with the same surface invariants. The original wiring is unchanged; the surviving loop and three distinct parallel bands must not be dropped. Ten is a chosen critical-point count, not a minimum or an intrinsic nuclear quantity.

Genus 5 is **not intrinsic** to the incidence graph: the checker also gives a different rotation system on the same graph with **genus 0** and **sixteen boundary circles**. The source retains a failed planar shortcut as well as the valid planar witness. This is a test of supplied surface realizations, not a derivation of the attachment convention from nuclear data.

## What the Morse description does not establish

The local minimum/saddle charts and collar argument describe a mathematical handle realization. The output is **not a computed smooth atlas**, numerical gradient metric, rendered differentiable mesh or physical energy landscape. Critical levels are construction levels, not physical time, SVG height or nuclear energy.

An acyclic arrow assignment is only a necessary consistency condition for strictly descending arrow values. It is not sufficient to identify those arrows with this Morse function: both endpoint vertices are minima with a saddle between them. Colored traversal is **not a gradient flow**, Reeb graph or Morse–Smale complex by declaration. Edited arrows are checked separately; an old acyclicity result cannot certify every edited document.

This is **not physical nuclear geometry** and **not experimental validation**. The Ne-20 name and proton/neutron reference facts do not supply a bridge from this authored incidence/rotation model to measured nuclear shape or dynamics.

## Verification and publication boundary

The application source names `pnpm check:morse-surface`; the separate [research/strominger/checkers/check_ne20_morse_surface.py](https://github.com/andrey-kokoev/marici/blob/main/research/strominger/checkers/check_ne20_morse_surface.py) reconstructs boundary permutations with exact rational arithmetic and checks a source-hashed TypeScript receipt. Its declared controls reject false genus, missing half-edges, changed rotations and lost contracted-port/vertex provenance. This source-described independent implementation is not proof-assistant certification or physical validation.

Those typed-app/compiler/Morse checks were **not rerun** for this editorial decision. No application UI, source incidence, constructor, native policy or scientific receipt is changed. No new application bundle is published. The existing source notes provide hypotheses and reproduction commands; this page does not convert them into independently replayed evidence.
