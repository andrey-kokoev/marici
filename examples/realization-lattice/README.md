# Realization lattice — space only

Three.js viewer of the four tetrahedrally oriented, equally spaced plane
families from the working plane example. No particle assignments, filled
preferred solid, coherence-complex search, or twelve-dimensional spatial
embedding is introduced.

## Run

```sh
pnpm lattice:dev
pnpm lattice:test
pnpm lattice:prepare
```

The dev command prints its local address. The build produces
`website/public/experiments/realization-lattice/index.html`, accessible as
`/experiments/realization-lattice/index.html` on the local website. Normal
website preparation also builds this viewer. No deployment is performed.
Three.js 0.180.0 and TrackballControls are bundled locally; no CDN is used.

## Six-carrier helium view

Choose **2 P + 2 N + 2 E tetrahedral bodies**, then **Show & frame helium**.
This is the exact prior retained helium-core geometry, not the four-wedge
interval relabelled as particles. Each constituent is a separate selectable,
labelled tetrahedron: red P, blue N, gold E. The coordinate map sends the four
source basis vertices to FCC indices 000,110,101,011 and preserves the supplied
incidence. Longer subdivision edges are dashed. Not all six carriers are
regular primitive honeycomb tetrahedra; their shapes are not altered to make
them regular. Reader/exit closure is not added by this display.

`helium-carriers.json` is generated by `node scripts/prepare-helium-carriers.mjs`
from the existing helium-3 constructor and helium-4 core probe. Use `--check`
to verify it against the live source without rewriting it. Tests verify the
six bodies, FCC vertex positions and shared P–N–E faces. The fixture carries
the original source vertices, keys and the unresolved exit flag.

## Earlier geometric interval overlay

Select **Earlier 1 → 4 → 1 interval test**, then **Show & frame helium** to inspect the tested 1 → 4 → 1 octahedron
on the actual lattice. The preset enables the overlay, ensures extent >= 2,
hides planes and the neighbour star, dims the background lattice, and frames
the candidate. Fit & reset returns to the whole lattice view.

Entry and exit are labelled. Four translucent wedges can be inspected together
or individually as W1–W4. Their common polar diagonal is dashed because it is
an added subdivision edge, not an elementary FCC edge. Wedge colours are not
P/N assignments. The preset is fixed to the checked origin fixture; it is not
a two-cell coherence search or attached to the currently selected vertex.

The interval branch of `helium.js` is tested against the exact Python role-test receipt. All six
candidate vertices coincide with lattice vertices; all twelve outer edges
are actual lattice edges. Desktop and emulated-touch tests cover the preset,
labels, wedge controls and overlay visibility.

## Geometry

For positive distance d, the four normalized tetrahedral normals n_i define

    n_i . x = d(1 + 4k), k integer.

Intersection vertices have coordinates

    x = sqrt(3) d (2m - (1,1,1)),
    m in Z^3, sum(m) even.

Neighbour offsets in m are permutations of (+/-1,+/-1,0). Thus an interior
vertex has twelve neighbours; elementary edges all have length 2 sqrt(6) d
and lie in two of the plane families. The finite window is a coordinate crop,
not a boundary condition. The plane patches extend beyond that crop as visual
aids and do not define finite disks as physical objects.

The four plane orientations are treated symmetrically. Optional colours identify
families without changing their geometry. At a vertex, a parallel plane of any
family splits the twelve neighbour directions as 3 / 6 tangent / 3.

These twelve local geometric neighbours have not been identified with the twelve
directed endpoint sectors of the tower's decorated field. That adapter remains
separate from constructing and inspecting the space.

## Controls

- Free trackball rotation, wheel/pinch zoom, including camera roll.
- Arrow keys rotate, Q/E roll, +/- zoom, F centres the selected vertex and R
  resets while the canvas is focused.
- Extent, distance, plane opacity and independent visibility controls.
- Click/tap a displayed vertex to inspect its local neighbour star. Screen-space
  picking halos are 14 CSS pixels for mouse/pen and 24 for touch. Nearest projected
  centre wins; depth breaks ties. Use the labelled vertex list for overlapping
  sites or keyboard selection. Drags and multi-pointer gestures are not taps.
- Centre selected preserves the current camera offset; Fit & reset returns to
  the central marked vertex and fits the current extent and viewport aspect.
- A compact scene legend and selection status distinguish full neighbourhoods
  from cropped ones. Family colours have accompanying text labels.
- Plane opacity is density-normalized against the patch count to reduce haze.
  Appearance changes reuse geometry. Extent/distance changes commit on release
  or after a 75 ms pause, rather than rebuilding on every slider drag frame;
  selecting a vertex rebuilds only its star.
- Plane patches and wireframe edges only; no selected tetrahedral interior.

## Rendering performance

Plane patches are instanced into four family draws (single-pass, double-sided),
not one two-pass mesh per disk. Translucent constituent surfaces also use a
single pass. DPR is capped at 1.5. Labels use cached viewport dimensions and
compositor transforms, avoiding interleaved per-label layout reads and writes.
Frame requests raised during rendering are coalesced into the current frame;
there is no idle render loop. Instanced buffers are disposed during rebuild.

See [the measured audit](../../research/realization-tower/lattice-performance-audit-v1.md).
`node scripts/profile-realization-lattice.mjs` runs the reproducible Chromium
software-GL profile. It measures callback CPU times and draw calls, not physical
GPU presentation latency. Translucent intersections retain sorting limitations;
family instancing does not implement order-independent transparency.

## Verification

Node tests verify integer plane incidence, equal edge lengths, two shared plane
families per edge, twelve interior neighbours, scaling and input bounds.
Chromium smoke tests verify startup, keyboard/list controls, actual pointer
rotation without selection, enlarged mouse picking, emulated touchscreen picking,
hidden-point nonselection, appearance changes without lattice rebuild, reset,
mobile layout and absence of page errors. Desktop/mobile screenshots are saved
under `research/realization-tower/results/lattice-ui/` and were visually reviewed.
The extent-6 geometry update previously took roughly 40–50 ms in a local run;
slider pause scheduling now adds up to 75 ms before that update. This is not a
device performance guarantee. Multi-touch exclusion is implemented but pinch behaviour
has not been automated-tested. This is not a cross-browser/real-device audit or
a validation of the tower interpretation.
