# Finite incidence kernel: closure and verification scope

## Implemented boundary

`finite-diagrams.mjs` is a headless ES module with no third-party dependencies,
DOM, storage, drawing coordinates, isotope dispatch, or physical interpretation.
`schemas.mjs` supplies a directed-graph schema and a provisional isotope-incidence
schema. The live SPA does not import this kernel yet.

The implemented object is a finite-set-valued diagram over a **fixed schema
presentation**. It is not yet a research revision, an attributed isotope model,
a physical structure, or an edit history. The schema presentation includes an
ID, sorts, arrows, and equations between composable paths. Equality compares the
normalized full presentation, not just its ID. Logically equivalent but differently
presented schemas need an explicit adapter, which is not implemented.

## 1. Ambient category and finite closure

Let S be the small category generated by the schema's sorts, arrows, and path
equations. An object is a functor

\[
X:S\longrightarrow\mathrm{FinSet}.
\]

The total input presentation has finitely many records of each declared sort.
Each schema arrow is a total map between its source and target sets. The kernel
checks every declared equation on every element of its starting sort. Satisfaction
of the generating equations gives a functor on the presented category; the
implementation does not enumerate all paths in S.

A morphism is a natural transformation. For every schema arrow `a:s -> t`:

\[
f_t X(a)=Y(a)f_s.
\]

The kernel checks the equation for each source record. Identity and composition
are componentwise identity and composition of functions; their category laws
follow from the corresponding laws for functions. Returned diagrams and maps
are deeply frozen. An unchecked plain object is not accepted as a map or diagram.

For a **finite** diagram of such objects, limits and colimits are computed
pointwise in FinSet. The induced incidence maps are well-defined by the cone or
cocone equations. The schema equations remain satisfied: for limits this follows
by testing all projections, and for colimits by testing all injections. Universal
factor maps are natural by the same componentwise uniqueness argument.

Thus this mathematical ambient category has finite limits and finite colimits.
This does not assert closure under arbitrary infinite constructions, or closure
of a model-valid subcategory defined by extra predicates. The mathematical
argument specifies the algorithms; bounded code tests are not a formal proof of
implementation correctness.

### Implemented constructors

| API | Input | Returned structural witnesses |
|---|---|---|
| `initial(schema)` | Fixed schema | Empty set at each sort |
| `initialMap(X)` | Checked diagram | Unique map from the initial object |
| `terminal(schema)` | Fixed schema | Singleton at every sort; unique incidence maps |
| `terminalMap(X)` | Checked diagram | Unique map to the terminal object |
| `coproduct(A,B)` | Same-schema objects | Object, injections, universal `factor(u,v)` |
| `product(A,B)` | Same-schema objects | Object, projections, universal `factor(u,v)` |
| `pushout(f,g)` | Maps with the same source | Object, maps from both targets, equivalence-class membership, `factor(u,v)` |
| `pullback(f,g)` | Maps with the same target | Object, maps to both sources, retained pairs, `factor(u,v)` |
| `equalizer(f,g)` | Parallel maps | Object, inclusion, universal `factor(h)` |
| `coequalizer(f,g)` | Parallel maps | Object, quotient, universal `factor(h)` |

`compose(g,f)` means g after f. Composition requires equal normalized boundaries,
not merely equal sizes or matching schema IDs. Factoring refuses incompatible
boundaries and noncommuting cones/cocones.

Finite products and equalizers suffice to construct arbitrary finite limits;
finite coproducts and coequalizers suffice for finite colimits. There is no
arbitrary-diagram parser yet. The listed constructors are the executable basis.

## 2. Pushout algorithm and its universal property

For `A <- K -> B`, form the disjoint union of the A and B records at each sort.
Generate the equivalence relation identifying `f(k)` on the left with `g(k)` on
the right. Union-find computes the finite equivalence classes. A quotient record
retains the list of its original side-tagged occurrences.

Incidence of a class is the class of any representative's incidence. Naturality
of the input span implies representative independence; the kernel also checks it.
Generated IDs name these classes within this output diagram. They are not global
occurrence IDs and must not be treated as immutable revision identities.

For a compatible cocone `(u:A -> Z, v:B -> Z)`, the factor maps each class to the
common image of its members. Compatibility makes this well-defined; the images
of A and B cover every quotient class, so the factor is unique. No image-based
heuristic or search for matching coordinates is involved.

In particular, identical record names in A and B stay distinct unless the input
span identifies them. Noninjective spans are allowed in the ambient category.
`isMonomorphism` checks componentwise injectivity so a stricter interface policy
can be enforced by a caller rather than silently assumed.

## 3. Pullbacks, quotients, and model constraints

For `A -> C <- B`, a pullback record is a pair `(a,b)` with equal C-images.
Incidence acts componentwise. Its universal map sends x to `(u(x),v(x))`;
uniqueness follows from the two projections.

The equalizer is constructed by pulling back `(f,g):A -> B x B` against B's
diagonal. The coequalizer is constructed by pushing out `[f,g]:A+A -> B` against
the fold `A+A -> A`. Both return the relevant universal factor constructor.

A directed graph's terminal object has one vertex **and one loop**. A quotient
identifying the endpoints of an edge also creates a loop. A no-loops model is
therefore not closed under these ambient constructions. The suite retains this
counterexample instead of deleting the loop to make the result look valid.

Likewise, the provisional isotope schema allows red and blue references to name
the same support edge. It checks endpoint and ownership equations, not a
no-color-conflict policy. A future model predicate may refute that candidate.
The structural kernel must not change its incidence to satisfy the predicate.

## 4. Open components and coherence

`openComponent(left,right)` constructs a cospan `I -> G <- O`.
`identityComponent(I)` is the identity cospan.
`composeOpen(g,f)` glues the output of f to the input of g using a pushout, and
returns both the composite component and its gluing witnesses. Boundary objects
must match exactly; use an explicit interface isomorphism/adapter to transport a
differently named interface. No adapter is inferred automatically.

The public API supports general cospans. If an application restricts both legs
to monomorphisms, pushout stability of monomorphisms in this ambient category
preserves that restriction under composition. Other restrictions need their own
closure argument.

For any parenthesization of a fixed composable sequence, the composed apex is a
colimit of the same chain of apex/interface objects. The comparison between two
parenthesizations is the unique map preserving every original apex leg. The
reverse comparison exists by the same property, and the two composites are
identities by uniqueness. Consequently the associator is an isomorphism.

Both routes around the associativity pentagon preserve the same original legs,
so uniqueness makes their maps equal. The tests build these comparisons from
universal factor maps, invert them, check boundary preservation, and compare the
actual component maps around the pentagon. Equal counts are not used as proof.

This establishes the intended cospan-composition semantics. A packaged bicategory
API, general 2-cells, parallel tensor on cospans, and executable triangle/hexagon
coherence interfaces are not supplied by this milestone. Ordinary diagram-map
composition must not be confused with the still-unimplemented edit calculus.

## 5. Provisional isotope schema

`isotope-wiring.incidence-proposal.v0` has sorts:

- shell, cell, port, vertex, edge;
- pair, lineWitness, boundary, boundaryWitness.

It explicitly records cell-to-shell and port-to-cell ownership, port-to-vertex
support, edge endpoints, red/blue routes, witness support, and boundary ownership.
Path equations make route endpoints and ownership agree. Boundary support is a
named object, not a certified closed geometric cycle.

This original schema does not itself provide model attributes, capacities,
metric data, isotope counts, or target predicates. The subsequent
[adapter milestone](ADAPTER.md) adds a support sort, shell-local lattice policy,
model labels, and retained-source legacy import without altering this schema.
It does not import screen-coordinate equality as structural identity.

## 6. Executed checks

Run:

```
node --test tests/isotope-wiring-category.test.mjs
```

Fourteen tests pass:

- malformed domains, dangling incidence, schema equations, naturality, immutable
  outputs, and full-schema boundary checks;
- identity and associativity for every endomap of a two-element finite set;
- 43 finite-set spans and 249 compatible cocones, including exhaustive uniqueness
  of factor maps to target sets of sizes 0–2;
- 59 finite-set cospans and 249 compatible cones, including exhaustive uniqueness
  from source sets of sizes 0–2;
- equalizer/coequalizer uniqueness for all parallel maps between sets of sizes
  0–2, with factor tests over the same source/target bound;
- graph-level gluing, support occurrence retention, noninjective spans, and a
  quotient-loop counterexample to model-constrained closure;
- open-component unit isomorphisms, a four-segment pentagon, and transport under
  an explicit input renaming;
- the provisional isotope schema's route/ownership equations and an identity
  pushout involving its nonempty pair records.

These are bounded tests. There is no theorem-prover certificate or SCC categorical
admission for this implementation. Exhaustive tests on tiny sets exercise the
universal-map algorithm but do not cover all schemas or input sizes.

## 7. Residuals and next structural gate

The prior legacy defects remain recorded in `tests/isotope-wiring-core.test.mjs`:
identity-delta replay, metadata deletion, and generated cell-ID collision.
They are not repaired by adding this independent kernel.

The next gate's implementation is documented in [ADAPTER.md](ADAPTER.md): model
labels, support-interface policy, and a loss-accounted adapter now preserve owned
occurrences separately from shared support and retain every source field.
[MODEL.md](MODEL.md) adds attribute-type predicates and policy-composition closure
checks. [REVISIONS.md](REVISIONS.md) adds immutable states and ground rewrites.
General frame/match transport and selective evidence transport remain open.

Do not connect the visual editor until those adapters and operations can be
replayed headlessly. No visualization or website behavior changed in this work.
