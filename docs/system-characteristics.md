its proposed physical interpretation, and the mathematical prototypes used to
test it. The current architecture groups all matching paths and promotes each
grouped record to a freshly labelled record for the next level. Earlier Gram

**Status:** **checked** means the stated construction has executable verification;
**conditional** means the conclusion depends on the listed model choices;
**open** identifies a missing construction or physical identification. Checked
mathematics does not establish a physical interpretation.

## System as a software architecture

The system is a recursive relational index with retained history. Within each
triple, the same records have three presentations: individual labelled records,
records indexed by from-label, and records indexed by to-label. Every group
retains all matching records.

Between triples, summarize the grouped records and assign each a fresh unique
label. The resulting interface is **fresh label ↔ grouped record** (1:1). The
many:many structure remains inside the record through retained members or links.
This is family promotion. The next level organizes families of relations, then
families of families.

Conceptual pseudocode for promotion:

```text
groups = summarize(current_records, grouping_keys, retain_members=True)
next_records = addcolumn(groups, "label", unique_index)
```

`retain_members=True` states the preservation requirement; ordinary aggregation
or deduplication alone does not preserve all member records. Grouping keys,
next-level endpoint fields, and label lifetime are part of the implementation
contract. A fresh index identifies a group within its declared namespace; its
stability across later updates requires an identity policy.
