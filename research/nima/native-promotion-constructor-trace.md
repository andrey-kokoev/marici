## Exact constructor sequence

Let c be the actual complete comparison.

1. **Existing in-place operation:** `exchange c` swaps both routes, their native histories and certificates, and reverses the effect witness. Its type remains `Previous.Compared -> Previous.Compared`.
2. **Next carrier:** the entire `Previous.Compared` type becomes an atomic code for the next compiler. It is not replaced by a decoded vertex or a scalar route count.
3. **Endpoint presentations:** A is the original presentation of that whole carrier; B transports its coordinates through exchange; C transports again through exchange. These are coordinate-equipped presentations, not seed graph vertices.
4. **Existing routes:** direct is one identity-effect step from A to C; via is two exchange steps through B. Both sequentially return c, while their route syntax differs.
5. **Native compilation:** compare-rule compiles the supplied steps; Pi-rule collects the step packages. `compare-compilations direct via c` keeps both histories, their certificates, and the equality of effects.
6. **Actual promotion:** `run c : Next.Compared`. `promoted c` packages exactly this result as a next complete input. A subsequent feedback instance consumes that exact value.

Only step1 is an in-place exchange. Steps2–6 construct a new comparison object with new outer routes. Conflating these was a major source of the earlier cross-model detour.
