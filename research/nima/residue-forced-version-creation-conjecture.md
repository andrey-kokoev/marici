# Deutsch--Popperian residue-forced version-creation conjecture

## Operational definition of a version

A version is not a timestamp, release label, or new notation.  A version
\(V_n\) is a frozen operational contract consisting of:

\[
V_n=(\mathcal T_n,\mathcal O_n,\mathcal C_n,\mathcal R_n),
\]

where \(\mathcal T_n\) is the family of admitted types,
\(\mathcal O_n\) the admitted operations, \(\mathcal C_n\) their declared
composition/coherence laws, and \(\mathcal R_n\) the authorized readouts.

A change of coordinates or implementation that preserves this contract is
not a new version.

## Conjecture

A persistent residue of \(V_n\) forces a successor version \(V_{n+1}\)
exactly when all of the following hold:

1. it is generated by a legal \(V_n\)-operation;
2. it is invariant under the declared equivalences of \(V_n\);
3. it obstructs a composition or extension required by the frozen objective;
4. the source independently derives a new type, grade, support object, or
   coherence map that absorbs it;
5. the extension is conservative on every previously valid \(V_n\) result;
6. no source-preserving splitting expresses the extension inside \(V_n\).

Then the migration

\[
\boxed{V_n\longrightarrow V_{n+1}}
\]

internalizes information that was only a relative residue at version \(n\).

The conjecture is Deutschian because version creation is explained by a
specific necessity: preservation of lawful composability.  It is Popperian
because each clause can fail independently.

## Compatibility classes

Residue does not automatically imply a version transition.

| Disposition | Test | Version consequence |
|---|---|---|
| absorbed | existing types and coherence transport it | no version change |
| declared extension point | existing contract already reserves its typed slot | compatible/minor realization |
| forced extension | source-derived nonsplit completion is required | genuine successor version |
| unresolved obstruction | no source-derived completion exists | blocked; no version authorized |
| fitted repair | target is added after inspecting failure | rejected |

## Variance correction: compatibility points backward

The notation \(V_n\to V_{n+1}\) is useful for historical succession but is
usually the wrong direction for the canonical structure map.  A successor
contract can forget its new field or coherence grade:

\[
\boxed{
\pi_{n+1,n}:V_{n+1}\longrightarrow V_n.
}
\]

The reverse direction is generally not a function.  One old-version value
has a fiber of possible successor values, and residue is the additional datum
that selects a point in that fiber.

For filtered jets,

\[
A_{d+1}\twoheadrightarrow A_d
\]

is canonical, while no unital algebra section exists.  Over \(\mathbf F_3\),
every \(A_d\) element has exactly three lifts to \(A_{d+1}\), distinguished
by the coefficient of \(x^{d+1}\).  An old value cannot infer that coefficient
from its own state.

Thus an honest upgrade is a correspondence

\[
V_n
\xleftarrow{\ \pi\ }
V_{n+1}
\xleftarrow{\ \text{source datum}\ }
\text{resolved execution},
\]

not a canonical coercion \(V_n\to V_{n+1}\).  In API language, a version-two
response can usually be downgraded to version one by dropping the new field;
a generic version-one response cannot be upgraded without obtaining that
field from the server, migration source, or another authority.

This corrects the phrase “residue accumulation creates a version.”  More
precisely:

\[
\boxed{
\text{a source-derived residue populates the new fiber of a conservative
successor contract.}
}
\]

Repeated compatible projections form an inverse tower

\[
\cdots\longrightarrow V_{n+2}\longrightarrow V_{n+1}
\longrightarrow V_n.
\]

Its limit is a completion only when the source supplies compatible data at
all depths.  Finite versions alone do not manufacture a point of that limit.

## Attack 3: residue forces adoption, not schema genesis

The filtered-jet positive control does not establish literal version
creation.  The ambient polynomial source already declares the entire tower

\[
\cdots\to A_{d+2}\to A_{d+1}\to A_d.
\]

The residue proves that \(A_d\) is insufficient for the stated continuation
objective and supplies the next fiber coordinate.  It does not invent the
type \(A_{d+1}\), its multiplication, or its projection.  Those came from the
source algebra independently.

Three events must therefore remain distinct:

1. **diagnosis:** a typed residue demonstrates that \(V_n\) is insufficient
   for a frozen objective;
2. **successor derivation:** source structure supplies a conservative
   nonsplit contract over \(V_n\);
3. **version admission:** an authority declares that successor contract to be
   the next governed version.

Only their composition produces a version transition.  Residue is evidence
and migration data; it is neither schema author nor admission authority.

Accordingly, the literal claim “residue accumulation creates versions” is
superseded.  The surviving conjecture is the
**residue-forced version-adoption conjecture**:

> Given a predeclared source family of admissible successor contracts, a
> persistent residue can force adoption of a particular conservative
> successor and populate its new compatibility fiber.  It cannot derive or
> authorize a successor family that the source has not supplied.

The jet example proves forced adoption inside a predeclared tower.  The
three-wall example proves the complementary no-go: when the proposed
successor fails source typing and no alternative has been predeclared, the
residue blocks continuation rather than creating a version.

This correction prevents a hidden homunculus in the conjecture.  Without it,
“residue creates the type that absorbs residue” simply relocates unexplained
design authority into the residue itself.
