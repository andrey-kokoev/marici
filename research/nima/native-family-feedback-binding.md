# Native feedback accepts keyed families, but does not select their former

## Iteration4 constructive result

A concrete generic Agda adapter now connects target-keyed families to the ACTUAL existing `Feedback.run`. It does not rely on the unrelated filled tetrahedral native fixture.

For explicit row type R, key type K and key:R->K, a family retains:

- its grouping endpoint k;
- a member type I;
- member:I->R;
- witnesses key(member i)=k.

Instantiate the existing native compiler on `atom Family`. Embed a family as the native comparison of two empty routes in its original presentation. Feed that exact comparison to the unchanged feedback constructor.

The resulting native output retains the whole family, not only its mean. An actual native decoder recovers it exactly. The module proves injectivity and preservation of ANY supplied family observation through that decoder.

This is an explicit declared adapter, not a claim that the original native filled-tetrahedron input has been derived from the seed. Empty-route preparation supplies no additional seed faces and no comparison discrepancy; the feedback output itself has the constructor's existing outer routes.

## Endpoint binding at the family level

The decoded family is the refined source field. Its decoded grouping endpoint is a target field. Equality of the latter preserves and reflects equality of family keys; equality of the source recovers the family.

The actual matrix promotion has another field that must not be conflated with that grouping endpoint: its GENERATED next target.

At each round:

    grouping key = the members' old target,
    generated next target = successor(grouping key).

The formal module includes a parameterized successor-port adapter and proves preservation/reflection of equality of those successor keys. Injectivity of successor is NOT assumed. This allows inherited keys or a common target but cannot choose between them.

## Exact actual-family audit

The checker freshly rebuilds the existing typed geometric record binding. For every family in both rounds under both policies it verifies:

- all members have the same old target key;
- member masses sum to a positive family mass;
- the original weighted mean equals the family value;
- generated endpoints obey the actual unchanged successor policy;
- the existing flat-frame transported response equals the family response;
- all137 original leaf labels/endpoints/values are retained;
- original J4 is unchanged.

The formal reader-square can carry the supplied mean because it carries the entire family. The reader-square does not derive the member measure or calculate matrices in Agda; these are supplied finite fields audited separately.

The critical profiles remain:

| Policy | First families | Second families | Members of each second family |
|---|---:|---:|---|
| inherited |32|32|one each|
| common |32|1|all32|

Both are admissible family inputs to the same native adapter. Native recoverability therefore cannot choose the generator.

## Constructor factorization, not an identity

The checked candidate chain is now explicit:

    decorated response rows
      -> incoming fibres with a supplied successor-port policy
      -> complete families with supplied mass/readout
      -> explicit atomic native comparison preparation
      -> actual Feedback.run
      -> decoded family and inherited readout.

This closes the previous family-INPUT binding gap. It does not turn native `run` into the incoming-fibre former. Family aggregation occurs before `run`; calling their composition T9 would be a new declared candidate, not recovery of an intended constructor.

In particular, replacing the family with only its matrix mean would discard retained members; retaining the family but copying its mean faithfully does not source-select its weights.

## Remaining selection, now localized

Record endpoint/value transport is bound conditional on supplied flat ports. Native family transport is also executable conditional on supplied families. The unresolved part lies BEFORE native feedback:

1. which admitted source family/record table is grouped;
2. which successor map takes old target keys to new ports;
3. which member measure and response question are intended.

Neither generic retention, table uniqueness, geometric response calibration nor native type ascent fixes these inputs. The productive next action is to inspect original constructor specifications for those requirements, not add another faithful wrapper and call it intended T9.
