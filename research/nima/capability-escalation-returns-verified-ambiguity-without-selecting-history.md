# Capability escalation returns verified ambiguity without selecting history

## Delivered request gate

A process-local fixed-family service now distinguishes failure to verify a tighter section from a proved history-dependent admission disagreement. It never selects the actual history from a witness, a candidate archive or self-declared provenance.

The workload passes thirteen refusal controls. A separate semantic replay imports no capability session, verifies the exact common section and the original-atom obstruction, and confirms that no selected history or admission answer is claimed. All thirty scalar-band certificates also pass fresh replay.

## Tighter lifting does not prove separation

Bootstrap checks an independently supplied family/n/eta contract against a complete scalar-band certificate. The session retains an immutable section and expected state.

A tighter tolerance requires a new full section check. Reusing the three-cell eta=1/100 construction at eta=0 fails even after its request header is updated. The service returns SECTION_NOT_VERIFIED, leaves the old checkpoint intact, and explicitly does not claim history separation.

Replacing it with the verified sixteen-cell eta=0 section succeeds and publishes a new handle. This proves a common exact section exists; the earlier failed selector cannot be presented as an impossibility theorem.

## Fine continuation returns a bound ambiguity

For the independently expected continuation h<=1/2 followed by exact admission of public point (1,1), the service checks the existing obstruction certificate. The point is bound separately to the caller's request, rather than accepted from the candidate certificate as its own authority.

The result is HISTORY_PROVENANCE_REQUIRED with:

    A admits the displayed point: false
    B admits the displayed point: true
    actual history: unselected
    selected admission answer: absent

The rejection for A is a checked scalar contradiction; B has a checked original-atom source witness. This concerns the displayed fiber, not emptiness of the entire refined A domain.

The request is not executed against an invented selected branch. No fine refinement is appended to the retained common state. The checked alternatives and their proof are retained as an ambiguity record, bound to the current state, exact operation and point.

The same ambiguity persists after installing the common zero-tolerance section. Common lifting and history-specific fine admission are different capabilities.

## Provenance remains an explicit open gate

No owning provenance authority is integrated. Consequently every history-selection request is refused, even when its metadata matches the current ambiguity.

Stale checkpoints, old request digests and mismatched provenance contexts are rejected before any selection could occur. Matching context is only a necessary negative filter; it is not authorization. Self-declared branch names, archives containing both alternatives, the positive B witness and an asserted issuer/signature all fail closed.

There is no token acceptance protocol, authenticated archive import, identity-recovery operation or branch-selection callback. A future authority integration needs its own owning contract and tests; this implementation does not simulate successful authentication.

## Retention and process boundary

Receipts charge live-state, full-section and ambiguity-proof encodings separately. The actual-history selector is absent and contributes zero retained selector bytes. The obstruction records the logical one-bit lower bound for selecting between two histories; it does not claim that an authenticated provenance token would occupy only one bit.

The session does retain both mathematical alternatives and their distinguishing proof. It does not retain a label identifying which alternative actually occurred. Handles identify checked session generations and contain no A/B selection.

Caller mutations of the supplied section and returned receipts do not modify the trusted snapshot. A successfully tightened section invalidates earlier handles and clears the old ambiguity context. Re-exposure is refused.

This is a trusted-process request adapter, not a hostile-memory security boundary. It does not return approximate atom lifts itself; that separate service remains in the Voevodsky lane. Encoded lengths are not a complete heap or archive ledger.
