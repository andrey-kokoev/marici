Does the proposed moving input–output division describe an actual existing WG
operation, rather than only reassociation of an abstract join?

Selected source: the existing generating horizontal schedule, inherited-key
fixture. It uses twelve primitive arrows, generates typed comparison slots,
and performs two incoming-family promotions. This is the declared candidate

## What was observed

| Step | Actual interface |
|---|---|
| Starting object | Twelve primitive arrow records, supplied role/reference context |
| Comparison generation | 121 arrow comparisons plus 16 state comparisons |
| Typed binding | Each slot retains its factors, two comparison witnesses and their filler |
| First incoming promotion | 137 leaves become 32 retained families |
| Second incoming promotion | Those exact 32 constructed families become the next operation's member inputs |
| Final package | 32 families, all 137 leaves and original primitive source recoverable |

The key check is direct structural equality: each second-stage family's member
is the actual first-stage constructed family. This is not inferred from an
equal scalar readout. At the inherited-key fixture, the second families are
singletons: their values and masses are unchanged, but their assembly labels,
source fields and target fields are fresh. They retain the prior family rather
than replacing it with its mean.

Every one of the 137 slots was independently checked against both comparison
witness boundaries and the filler boundary equation.

## What makes the step more than regrouping a fixed join?

The actual horizontal construction generates new comparison records with typed
factors and witnesses; it is not just a permutation of the twelve primitive
arrows. The first promotion creates family records, and the next promotion
accepts those records as its inputs. The typed interface changes even where
the numerical value does not.

By contrast, the existing vertical source-indexing operation reconstructs the
same twelve records. It is explicitly a retained presentation change, not the
same operation as comparison generation or selecting one source fibre.

This supplies an operational distinction, not a claim of physical time or a
newly derived dynamical law. Output-to-input reuse and retained construction
were already present in the source; this test checks their relevance to the
new interpretation rather than announcing them as newly invented mechanisms.

## Five hostile controls

The owning validators reject:

1. Erasing the original source parent.
2. Erasing the construction trace.
3. Deleting a selected nonzero comparison filler.
4. Keeping outer values but deleting retained family members.
5. Applying the full horizontal generator directly to its right-side output.

The last result is important: the full horizontal generator is not an
endomorphism of one object type. Actual staged reuse is established; arbitrary
iteration of G, or a complete return to rung12, is not supplied by it.

## Surviving interpretation

> A constructed, witnessed output becomes an established input to the next
> typed operation, with its prior members and coherence data retained.

That statement is realized by the tested WG schedule. It sharpens the
input–output-division intuition without forcing a false count correspondence.

The stronger claim remains unbound:

> Each numbered rung transfers one marked apex between two join factors of a
> fixed fifteen-element carrier.

The actual counts are 12 -> 137 -> 32 -> 32, in different record types. No
canonical fifteen-token partition, one-vertex transfer or join-factor adapter
was found in this operation. This does not rule out a separate decorated
realization or a suitably defined block-level transfer; it does rule out
reporting this test as verification of the proposed numerical table.
