# Allocator high-water is an execution premise

Fresh inspection: `Net.fresh(prefix)` increments one global integer serial and returns prefix_serial; `add` only detects collisions later. `Twin.__init__` starts at serial zero, builds data via fresh, and uses unsuffixed COPY/Q names plus OUT1/OUT2 as fixed roots. A sufficient execution invariant is serial >= every numeric allocation suffix of a live agent, with monotonically increasing serial and no external insertion or reset. Each fresh call then returns a new suffix larger than any prior live one; successive preallocated slots are distinct even before insertion. Deletion preserves the inequality. This is an inductive allocator argument for constructor-origin executions, not a graph property.

Fresh `check_allocator_execution_invariant.py` verifies high-water preservation on 219 exact fixture states and 452 edges. It also constructs a concrete counterexample by resetting the serial on an otherwise valid empty-support graph: COPY--N allocates a name already owned by a surviving budget NIL. The graph validator still passes; executable rewrite asserts on duplicate insertion. Thus the graph invariant alone is insufficient for safe executable reduction on imported/renamed graphs. The existing replacement API is not transactional on malformed execution state.

The abstract boundary commuting lemma remains sound with genuinely fresh replacement names. For the implementation, explicitly require the allocator execution premise (or redesign import/allocation to reserve disjoint names). No engine behavior was changed this turn.
