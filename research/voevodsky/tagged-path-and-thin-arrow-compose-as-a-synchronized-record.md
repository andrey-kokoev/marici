# Tagged path and thin arrow compose as a synchronized record

Keep BOTH a verified formal rotation path and its projected thin Tamari endpoint arrow, along with the declared primitive row-root IDs, in one record. Composition concatenates fine paths only when their intermediate bracket trees and roots match, and simultaneously composes thin arrows by endpoint reachability. The projection preserves composition because the concatenated path has exactly the composed thin endpoints. Fresh `check_tagged_thin_product.py` checks the four-leaf short and long pentagon routes: they have the same thin arrow and different fine records. It refuses omitted roots, a forged thin endpoint, mismatched composition endpoints, and an attempt to use the thin arrow as actual-execution authorization.

This is a clean mathematical PRODUCT/FIBRED record interface: one may consume the coarse reachability view without discarding exact fine syntax. The root IDs in this checker are DECLARED row identities, not independently authenticated owners; their equality is necessary for typed concatenation but insufficient for a claim that a real provider executed the rotation. The thin arrow is derived data and cannot be inverted to reconstruct a lost fine path.

The next problem is whether source-rooted support can be made independently verifiable rather than just matched by row-ID strings. A source DAG would need primitive proof-row evidence and a support edge for each elementary rotation; a hand-written root label alone is not evidence. The analytic S,A,R,C,G assignment remains a separate deferred gate.
