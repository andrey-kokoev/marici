# A seven-account retention ledger replays the fixed source-edit workload

For the frozen P->Q->P source-edit workload, one direct record keeps old primitive rows, current primitive rows, the record's source binding, endpoint proof P, intermediate proof Q, the ordered edge plan P-Q-P, and target normal/bound. The signed edge vector can be recomputed as Q-P and independently checked against BOTH manifests; it need not be stored redundantly in this particular encoding. Fresh `check_bounded_replay_retention.py` replays the y-high and coupled-bound cases, refuses omission of each of the seven listed fields, and rejects mutated Q and changed edge plan.

Owner-status information is a DIFFERENT account: if a local owner-registry observation is omitted, the correct verdict is `UNKNOWN_UNATTESTED`, not permission and not a globally authenticated claim of revocation. The included observation merely records 'no admitted owner in this local fixture'; it is not an independently attested registry. The ledger measures neither bytes nor universal minimal storage, and alternative encodings (e.g. a trusted manifest reference rather than all row bytes) could change which serialized fields are necessary.

The scoped answer is that mathematical replay, path ordering, source identity and potential authority each need an explicit retained input or an explicitly trusted reconstruction route. The next gate should test a compressed manifest-reference encoding against offline unavailability: can a proof remain independently replayable if only a digest is kept but the referenced old rows are removed? Analytic S,A,R,C,G correspondence remains deferred.
