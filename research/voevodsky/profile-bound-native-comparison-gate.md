# Profile-bound native comparison gate

Fresh resume selected `profile-bound-native-comparison-gate:v1`.

## Result

`agda/ProfileBoundNativeGate.agda` closes the constant-observation substitution
loophole for the concrete retained tidal application. It supplies a closed,
profile-indexed native package factory and comparison gate:

- the electric profile has the actual independently computed native electric
  payload;
- the joint profile has the preceding electric/gradient payload;
- the factory retains the selected source packet and exact profile, including
  denominator 13824 and fixed nonrotating corner frame;
- a reader must agree on ALL payloads with the declared calibrated slot reader,
  rather than merely matching one sample or carrying a profile label;
- a gate contains both reader authorizations and the actual native observed
  comparison certificate.

The canonical reader is identity on already calibrated integer coefficient
slots. This is not a derivation of the physical readout from raw source physics.
The earlier source-to-native computation and supplied analytic interpretation
remain separate evidence.

## Checked consequences

1. Source/profile header equalities and package equalities connect the factory
   to the actual preceding native electric package and encoded joint package.
2. Any admitted gate normalizes to a comparison preserving the canonical reader.
3. The selected electric comparison is admitted.
4. No gate admits the selected Newtonian/Rosen joint comparison.
5. No constant joint reader can meet reader authorization. The proof works for
   ANY constant value: the two actual gradient readings differ.
6. Identity, inverse and composition preserve this gate. Normalization avoids
   requiring syntactically identical reader presentations at an intermediate
   object.
7. The gate generates the actual owner's native comparison rule. A retained
   certificate package keeps its output and gate evidence, with recovery.

Two negative compilation controls reject the necessary constant-reader
calibration equality and the gradient-shift preservation equality. The positive
module proves the universal constant-reader exclusion and joint-gate exclusion;
the negative controls are deliberately smaller failed obligations.

## Exact scope

Authorization here means type-level conformance to this declared application
policy. It is not an operator permission, an owner adoption, or a compiler proof
of continuum field equations. No owner source was modified.

The gate operates on the two fixed profiles and selected source factory; it is
not a classifier of every arbitrary native package. It cannot be bypassed by
passing an electric-only view while requesting the joint profile. Changing the
policy itself would change the theorem's assumptions, not create a valid gate
under this policy.

The owner's unrestricted comparison API remains available. Applications must
actually require a `Gate`; projecting its raw rule alone does not make all other
call sites safe. Certificate retention is not an automatic proof that a new
source policy admits the retained package.

This establishes the requested local application-level gate, not a global
constructor policy. The next work returns to the existing
`construction-observation-compatibility` frontier: extend authorization through
actual native constructors, starting with dependent selection and product, while
retaining branch/profile information. Metric completion and physical source
admission remain separate obligations.
