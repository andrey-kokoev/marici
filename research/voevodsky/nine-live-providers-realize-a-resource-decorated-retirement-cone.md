# Nine live providers realize a resource-decorated retirement cone

## One diagram, one owning migration

The earlier geometric cone and resource tests used different bases. This control puts nine actually verified provider sessions into ONE diagram for the owning forced-zero-tail migration. Its complete public domain is the segment (u,u), 0<=u<=1, and its source section is (u,0,0).

The vertices are:

- B: a live provider restricted to 0<=u<=1/2;
- T0,...,T3: four full-domain providers;
- R0,...,R3: their independently admitted, publicly restricted counterparts with 0<=u<=3/4.

Every session bootstraps the SAME independently expected owning migration and retains lift capability without archive re-exposure. These are parallel comparison sessions, not forks illegally published from one linear checkpoint.

## Different presentations, certified provider substitution

The four full-domain section meshes have knots

    (0,1), (0,1/2,1), (0,1/4,3/4,1), (0,1/3,2/3,1).

Their section digests differ. Each attachment verifies full-domain coverage, every source vertex and segment-cell coherence using the existing exact attachment checker.

At every stored vertex (u,u), the source lift is (u,0,0). Hence each cell interpolates exactly the same source formula, independent of the mesh. This is a whole-domain provider-equivalence certificate, not merely agreement at the test points. The source admission and exact fine evidence were established by the owning migration and attachment gates.

This allows a substitution more general than the earlier unchanged-provider rule: retained encodings may differ when a checked comparison proves they realize the same promised task on the scoped base.

## Arrows and resource premises

An arrow from one vertex to another certifies:

1. inclusion of the source vertex's scoped public domain in the target's;
2. equality of the admitted fine-lift formulas on that scope;
3. the same owning migration binding;
4. available lift context and actual retained section data;
5. a currently valid process-local provider handle;
6. no inferred archive or original-history-selection capability.

The arrow is a comparison by restriction of a provider, not an operation that widens a live session's domain. Operational transitions constructing the R vertices only append public evidence; none widens a domain.

The whole diagram therefore lives in the fixed task contract of exact source lifting. It does not identify entire operational objects across differing query domains or silently install arbitrary new-query/archive capabilities.

## Based cone

The common base B survives every displayed public restriction: u<=1/2 implies u<=3/4. Its provider and scope remain fixed. The two presentation chains and their restriction comparisons form a diagram of shape

    B * (Delta^1 x Delta^3).

The four top staircase paths are

    B,R0,T0,T1,T2,T3
    B,R0,R1,T1,T2,T3
    B,R0,R1,R2,T2,T3
    B,R0,R1,R2,R3,T3.

Each consists of five verified arrows. All fourteen parenthesizations per path give the same endpoint comparison and common source formula. This checks 56 parenthesizations, with 120 actual provider interpolation calls as additional controls.

Composition forgets intermediate presentation identity only in the SEMANTIC comparison result. Retained section certificates and live provider checks remain prerequisites. It is not a proof that all program execution traces or storage costs are identical.

## Hostile resource change

After checking the diagram, the workload advances T0 through a real additional public refinement. Its old handle is now stale. The previously captured descriptor and section hash still look mathematically valid, but attempting to use that old provider in a fresh cone edge is refused.

This demonstrates why static formula equality and a positive capability field cannot replace live resource authority. The cone is certified for the admitted provider generations. A later generation change requires a new live comparison; historical equality certificates do not resurrect a stale service handle.

The separate allocation-detachment control remains the stronger example of losing a task rather than merely changing a generation. It is not spliced into this cone: it has a different underlying semantic base and source contract.

## What is now closed

A resource-decorated nine-vertex cone is now realized on one real retirement family, including actual provider substitution, public restriction, full scope coverage and live-handle checks. The base identification is supported both geometrically and operationally for the declared lifting task.

The original analytic S,A,R,C,G roles and residue jets are STILL not identified with these vertices. This family has an especially simple fine inverse; it does not establish the same cone for all scalar-band or rank-two systems. Nor does it give physical resource impossibility, externally authenticated history provenance or minimal total storage.

Nine independent sessions duplicate source/fine context and section information. The result is a coherence control, not a compression benchmark. Shared code, repeated owning verification and the calls made to compare providers all remain work outside any small live-state bound.
