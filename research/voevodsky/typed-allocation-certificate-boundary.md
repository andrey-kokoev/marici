# Typed allocation certificate boundary

Added `certified_replacement.checked_replace`, a separate wrapper over the pure evaluator. It checks exact declared old/new port signatures, admitted oriented principal kinds, canonical allocated names, globally unique live serials, live serials below the supplied pre-step high-water, and exactly the allocation interval (before,after] for fresh agents. Fresh declarations may be listed in an order different from allocation order. Only RET/ACK are fixed unnumbered roots in this combined-runtime profile.

Fresh tests compare234 captured replacements through scanner/conditional/query/union execution and reject six tampered witnesses (stale high-water, interval gap, wrong new arity, missing pair admission, noncanonical serial, reused serial). Rejections leave input dictionaries unchanged. Tests consume the explicit combined-signature audit artifact; they do not independently authenticate that table.

The name 'certified' denotes checked local certificate conditions, not formal certification. An authentic historical high-water is still a caller premise: no live graph can reveal all deleted IDs or detect a forged historical witness consistent with current live names. The wrapper does not prove the wiring is the correct semantic template merely because the pair and port types are admissible. It does not change production allocation or mutation behavior.

Next close that precise gap: use a declarative, allocation-slot-normalized rule-template manifest and compare production certificates against it, keeping the manifest independent of the current step call. A swapped but linear operand routing should fail even though current signature/allocation checks accept it. Do not claim imported-state recovery from this witness layer alone.
