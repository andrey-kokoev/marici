# A frozen proof-use request is not a source publication grant

For the frozen four-row square manifest, a local request object binds `authorize-future-source-rooted-proof-use`, source ID and canonical manifest SHA-256, a digest of the exact proof packet for x<=1, and explicit `source_generation=null`, `owner=null`, `status=LOCAL_UNAUTHORIZED_REQUEST`. Fresh `check_proof_use_request_envelope.py` saves this intent under `results/proof-use-request-envelope.json` and refuses altered multipliers (`PACKET_SUBSTITUTION`), changed action (`ACTION_SUBSTITUTION`), and an attempted current-use check with unknown generation (`SOURCE_GENERATION_UNASSIGNED`). A fictional generation match merely returns `REQUEST_FIELDS_MATCH_NOT_AUTHORIZED`.

An immutable request digest is useful for later binding to precisely the intended proof, but proves neither that an issuer exists nor that any owner has approved this packet. Since no authorized recipient or live source generation is designated in current evidence, this local object is not sent as an owner message or inserted as an authoritative Site event. Any future grant would have to name the source event, issuer, generation, exact action/packet and revocation route in an independently verified atomic snapshot.

Next test PACKET REPRESENTATION: the same x<=1 target can have distinct valid Farkas multiplier packets on the square, so a request scoped to one packet hash must not silently authorize another mathematically equivalent certificate. If a future owner intended target-level permission, that would need an explicit different scope. Analytic S,A,R,C,G remains deferred.
