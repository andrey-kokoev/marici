# An integrated local tagged/thin verifier separates five failure types

A bounded independent checker now verifies, in one pass, an assumed primitive unit-square source anchor, four exact Farkas leaf certificates, two syntactically valid labelled rotations, acyclic source-rooted support for their edges, and a thin arrow equal to the fine path endpoints. Fresh `check_integrated_tagged_thin_verifier.py` accepts the concrete short four-leaf path and separately refuses: changed source-bound anchor, invalid rotation, unrooted/cyclic dependency, forged thin projection, and an actual-execution authorization claim. This integrates the previously separate record and proof-DAG gates with typed failure locations.

The verifier's mathematical verdict is deliberately `MATHEMATICALLY_VERIFIED_LOCAL_RECORD`, not `authenticated operation`. Its source row anchor is embedded in local code, and a successful hash comparison is integrity relative to that assumption; it does not certify a provider, time of execution or ownership. The rotation checker proves that recorded adjacent trees are related by the formal rule, not that a real person performed it. The thin view remains derived data, while the exact fine path is retained.

This closes the LOCAL synchronized-record verification leaf. A nonredundant next branch is independent provenance of the source anchor (who attests primitive rows, under what capability, and how revocation affects future replay) rather than another purely formal pentagon enumeration. Only an owning authenticated surface could supply that authority. Analytic S,A,R,C,G correspondence remains deferred pending its distinct role/edge/base map.
