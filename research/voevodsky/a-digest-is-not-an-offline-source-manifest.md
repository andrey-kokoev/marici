# A digest is not an offline source manifest

Replacing retained old primitive rows by their SHA-256 digest is safe for independent replay ONLY if the exact old row bytes can still be fetched from an available content-addressed store and checked against that digest. Fresh `check_digest_only_manifest_replay.py` accepts an available matching old manifest, refuses an absent source (`UNAVAILABLE_OLD_MANIFEST`) and refuses substituted bytes under the old digest (`REFERENCE_DIGEST_MISMATCH`). With the store offline and only the digest retained, the old source equations cannot be independently rechecked.

This is not merely an implementation inconvenience: the old unit-square rows and the different coupled-bound singleton rows give the SAME image for the selected P and Q proof matrices, while their source digests differ. Those proof vectors do not reconstruct the lost primitive row statement. A hash names bytes; it does not supply them, select an actual owner or guarantee availability. External archival storage moves retained cost to a different account and demands its own horizon/capability contract.

The fixed-workload retention conclusion is therefore disjunctive: retain exact source rows locally, or retain an independently available immutable source locator with digest verification. Neither option is an authenticated provider admission or proof of minimal physical bytes. Next test availability changes after initially successful replay: retained old mathematical verdicts may remain valid, but a fresh independent replay must fail closed if the content-addressed store is later unavailable. Analytic S,A,R,C,G correspondence remains deferred.
