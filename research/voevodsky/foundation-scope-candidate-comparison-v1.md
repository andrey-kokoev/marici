## Important quantifier and finiteness correction

Finite constructor syntax does not imply finite data. `atom : Type ℓ → Code`, family-indexed Pi and map/equivalence attachments admit supplied higher/infinite data. A resolution application can have an infinite index family. Therefore even a bounded-depth well-founded derivation is not automatically a finite executable tree or a finite serialization. A future effective fragment must independently restrict arities and supplied data, then state that restriction instead of claiming it follows from the table representation.

The existing native equivalence transports actual source certificates and selected values, including supplied functions and paths. It does not reconstruct those from an endpoint readout. The current theorem is a meaningful prior foundation candidate stronger than the one-step Boolean adapter; it is still not physical generation or a proof of all mathematical validity.

## Identity choice cannot be hidden in an incidence

The two-sided transport note distinguishes a witness in F(a,b) from a path a=b. Path transports along each coordinate have a canonical comparison by identity elimination; directed maps need separately supplied squares. In set-valued fibres, comparison proofs cannot be used to encode arbitrarily distinct higher fillers. Higher-valued fibres retain that distinction.

Accordingly the candidate F/K record must say whether it admits only set-valued tasks or higher paths, and whether an operation is path transport or an independently supplied directed map. No formula based solely on incidence, regrouping or a scalar creates that licence. The cited note contains a written HoTT argument and finite semantic illustrations; this turn does not report it as a new machine theorem.
