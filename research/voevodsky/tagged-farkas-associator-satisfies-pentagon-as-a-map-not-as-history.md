# Tagged Farkas associator satisfies the pentagon as a map, not as history

For four separately tagged source-rooted Farkas proof leaves a,b,c,d, the formal rotation `((a,b),c) -> (a,(b,c))` preserves ordered leaf labels and the summed proof matrix. From `(((a,b),c),d)` to `(a,(b,(c,d)))`, the standard SHORT route has two rotations and the LONG route three. Fresh `check_tagged_proof_pentagon.py` replays both, checks their identical labelled final tree and identical final packet `(1,3,1,3)`, refuses omitted primitive source roots and reused leaf identities.

The pentagon thus COMMUTES as a function on tagged tree presentations: both routes send each valid tree to the same final tagged tree while preserving proof packets. But fine replay returns two different rotation histories (two steps versus three). If rotations are proposed proof-comparison cells, identifying these histories requires an explicit higher pentagon filler, not merely equality of their target tags. The source-rooted DAG must support that filler independently of the row roots which already support the four leaves.

This is a bounded set-valued solution to retaining candidates through composition, with a clear hierarchy: bare packet sets lose derivation multiplicity; tagged trees retain it; formal associator maps are coherent extensionally; proof-relevant associator HISTORY coherence is a further unsolved cell. The analytic S,A,R,C,G assignment remains independently deferred.
