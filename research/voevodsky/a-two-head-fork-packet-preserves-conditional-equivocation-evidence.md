# A two-head fork packet preserves conditional equivocation evidence

A bounded fork-evidence packet retains BOTH competing checkpoint heads, their common issuer/source/event/epoch/sequence scope, different row digests and proposed client delivery metadata. Fresh `check_fork_evidence_packet.py` writes the packet and checks its structural boundary. It refuses a missing head, a different issuer slot and identical heads. Supplying self-declared issuer-trust and transport-attestation strings does NOT make it authenticated; the gate explicitly returns `EXTERNAL_AUTHENTICATION_NOT_IMPLEMENTED`. Without those independent trust inputs it reports only a `CONDITIONAL_FORK_PACKET_UNAUTHENTICATED`.

This completes the local offline-audit diagnostic: hashes check integrity of bytes, a trusted checkpoint conditionally pins one branch, cross-observation comparison can exhibit a witnessed fork, but none of these locally constructed strings designates a real Farkas row issuer or proves globally fork-free publication. A single selected head would erase the very conflicting witness needed for dispute resolution. The mathematical source rows and past audit claims remain separate record types with different verification requirements.

A new substantive branch should examine whether an **existing owned append-only publication surface** can export an independently checkable checkpoint/consistency witness for THIS source; if no owner is admitted, treat the fork packet as research evidence only and pursue local graph/proof architecture independently. The analytic S,A,R,C,G role assignment stays deferred.
