# Native RH fixture integration

## Question

Do the independently checked cyclic, pasting, completion, and promotion contracts compose into one typechecked fixture object?

## Claim boundary

The integrated object is an integer fixture realization. It does not establish that every signed-even kernel realization is naturally identified with this fixture, and it does not establish source-global naturality.

## Construction

`RHNativeFixture.agda` instantiates three identical integer vertices with directed identity residue transports, a common-fiber cube, the exact integer pasting complex, an identity completion cone and preserving adapter, and child/parent residual towers. The current promotion gate has the empty type as its authority type, so this fixture constructs no parent re-entry capability.

The exported fixture theorems include unrestricted middle exactness, filler uniqueness modulo local adjustments, and completion preservation. They are imported through their native types rather than repeated as string-valued statuses.

## SCC reconciliation

The SCC overlay remains an admission and dependency projection. The native fixture refines it with obligations that SCC does not check: cubical boundary typing, the chain identity, middle exactness, filler comparison modulo adjustments, completion preservation, and explicit promotion authority. This does not modify or silently strengthen the SCC compiler.

## Disposition

The native components compose and typecheck as one fixture. The next source-sensitive gate is a typed map from the signed-even kernel family and its declared transports into this integer fixture, with naturality paths for generators, coherencers, and completion maps.
