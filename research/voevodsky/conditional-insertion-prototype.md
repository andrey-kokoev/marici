# Conditional insertion prototype delivered

`checkers/conditional_insertion.py` implements WAIT/PICK/JOIN/JOINR exactly as specified in `conditional-insertion-completion-contract.md`. It reuses acknowledged query, strict insertion and acknowledging erasure. No host Boolean dispatch is used: TRUE/FALSE principal pairs select the budget. The snapshot OUT identity is preserved and receives a newly allocated Boolean with the same value.

Fresh headless `check_conditional_insertion.py` passed 1,344 executions and 25,344 rewrites. Inputs cover every word of length<=2, query and both branch indices0..3, with cleanup-first, insertion-first and seeded random scheduling. Both Boolean rules and both completion orders execute; forced orders are asserted, not inferred from random coverage. Every actual replacement uses every external/fresh port exactly once. Final word/snapshot, original output identity and count2n+i+2k+l+10 pass. WAIT eligibility excludes all remaining query work, final ACK is absent while reductions remain, and final agent kinds exclude controls and K budgets.

These bounded tests support the written ownership proof, not arbitrary conditional composition or formal Python verification. In particular the final agent-kind check is weaker than an exact component accounting check. Next embed this conditional's support and acknowledgment interfaces into a strict successor query gate, verify that no successor can start before rejected-budget cleanup, and audit the exact final connected components. This tests the new two-workload join as a usable continuation, rather than merely as a terminal result.
