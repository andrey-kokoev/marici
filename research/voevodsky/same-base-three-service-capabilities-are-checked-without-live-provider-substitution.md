# Same-base three-service capabilities are checked without live-provider substitution

The existing `checked_retirement_interface.py` already supplies a stronger same-base test than the abstract three-atom fixture: from EACH independently verified owning migration it constructs answer-only, lift-enabled and archive-enabled states with identical `migration_binding`. `check_checked_retirement_lifecycle.py` takes two real owning projection cases, tests public refinement and fresh answer verification, a fine source lift and original fine re-exposure with the same later public frame, and rejects stale answer packets, answer-to-lift, lift-to-archive and nonpublic-frame escalation. An empty later public state cannot be lifted or silently reopened by archive re-exposure. Factory construction checks the owning migration case, but direct dataclass construction is not a hardened security boundary.

Fresh execution initially failed because the ambient Python lacked `sympy`. Running `uv run --with sympy python research/voevodsky/checkers/check_checked_retirement_lifecycle.py` passed: two owning migrations, 14 rejected lifecycle violations. The underlying Grothendieck projection verifier also reported five exact projection/compaction certificates. The test reports retained answer descriptor, optional lift context, optional archive and migration packet bytes separately. Importantly the lift context contains fine rows; it is NOT an information-theoretically smaller archive. Capability restriction is an API contract, not deletion or secrecy of the underlying formula.

The same-base three-service test still lacks live provider-generation handles and certified replacement across differing section meshes. That latter test exists on the forced-zero migration in the nine-provider cone, but is not combined here with archived fine re-exposure. A single-base combined deletion/substitution/re-exposure adversarial workload remains an implementation frontier. It can be owner-local if it composes independently authorized sessions as consumers without changing owner code; a wrapper must not fabricate archive grants or treat old handles as current.

This revises the earlier specification's implication that only a distinct toy fixture had tested answer/lift/archive capabilities. The result is narrower and stronger: SAME-BINDING service separation is verified on two real migrations; live generation replacement is separately verified on another real migration. No single existing run tests all four claims together. SCC classification: fixed-base static capability ports now have executable witnesses; live cross-provider route compatibility and archive combination remain uncompiled.
