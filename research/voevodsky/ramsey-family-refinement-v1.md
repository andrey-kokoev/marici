# Native prepared-family refinement: L_3 into L_4

## Scope and order

Node `native-family-refinement-transport` tests two specific prepared-input cutoffs. First construct the source extension and native seed/derivation map; only then compare query observations. The 365-point family is not asserted equivalent to the whole 171-point input package.

The old coloring is the restriction of the supplied new coloring through the region embedding. This is a premise, not a consequence of geometric containment.

## Source construction

Replay the original L_3 preparation in its original order, keeping its source bank alive. Append exactly the 194 new L_4 boundary points using the same geometry, reference-completion, packet and PN-validation APIs. Take fresh snapshots of the old live contexts after extension and compare every field, including opaque identifiers, outside references, five-slot packets and native interfaces.

The old 171 complete context strings must occur unchanged at the embedded new indices. A fresh lexicographic rebuild is a distinct rival: its geometric points can agree while its old namespace and quoted context values change. An explicit renaming might repair that rival, but no such renaming is assumed here.

Both indexed input families remain separate from a simultaneous occupied assembly, and no packet trajectory between preserved M-planes is introduced.

## Actual policy and derivation transport

The generated safe Cubical instance embeds the old index type into a new 365-constructor type. Under any new color function, the old word-query module is instantiated with the restricted function. Literal context equality gives equality of the old and embedded new native atom packages, including their colors.

An old seed certificate (i,p) is mapped to (embed(i),p followed by the fiber equality). Native `Resolve` is then mapped recursively on its real `seed` and `apply` constructors, keeping each state, rule declaration and argument header unchanged. A state-indexed constructor-history theorem retains every rule/premise structure and all state values at leaves. Seed certificates themselves change type through the displayed inclusion; this is not a claim that differently scoped certificate values are literally equal.

The old native word-query result is consequently an actual derivation under the enlarged policy. The direct L_4 native family/program/query is constructed separately. A further native P-family retains **both** result derivations; neither history is discarded in favor of a common scalar answer.

## Common observations

For all 27 fixed length-three requests, compare:

- the request and its canonical-trace observation;
- the declared lattice point, accounting for the distinct coordinate offsets;
- the whole selected context string;
- its supplied color under the restriction premise.

The two result packages have different index domains and different full prepared inputs. These overlap equations do not supply a whole-package equivalence or invert the cutoff inclusion.

## Strongest rivals

A freshly rebuilt L_4 family is source-valid and can give matching point/color readouts. Its native-only program must typecheck. The unprovided literal old-context inclusion must nevertheless fail typechecking: matching readouts do not repair a missing source map.

Additional controls change an old reference, remove an old context, alter a boundary interface or embedding, inject a requested answer into source preparation, use a wrong embedded seed certificate, or change a direct query index after a valid transport.

Sector geometry/reference data are runtime checked and quoted into Agda. The safe proof concerns the actual native WG constructors and declared point observations under explicit prepared-input policies; it does not prove the physical admissibility of those policies or interpret sector JSON in the kernel. No all-region/cofinal completion, arbitrary-word theorem or Ramsey forcing follows from this two-cutoff test.
