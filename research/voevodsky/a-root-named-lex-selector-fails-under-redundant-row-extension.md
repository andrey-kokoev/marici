# A root-named lex selector fails under redundant row extension

For square target `(1,1;bound=2)` the frozen old candidate set contains `p=(0,1,0,1)`. Adjoin exact redundant row z:`x+y<=2` and use the new candidate set `{i(p)=(0,1,0,1,0),q=(0,0,0,0,1)}`. Both are valid exact proofs and retract to p. With roots x-low, x-high, y-low, y-high, z-diagonal, lex on alphabetically sorted ROOT-NAMED multipliers chooses q, since its x-high coordinate vanishes. Thus `select_new∘include` is not `include∘select_old` under this explicitly frozen finite candidate convention; by contrast `retract∘select_new=select_old∘retract` happens to hold because both proofs retract to p. Fresh `check_root_policy_redundant_extension.py` checks the equations.

This is a failure of this named-root lexical policy, NOT an impossibility theorem for all source-rooted selectors. Prioritizing zero *new-row* mass selects i(p) on this candidate set and repairs its inclusion square, but that relative policy needs a typed old/new-root inclusion, not merely root names. In particular the added row creates a new history not present in the old source: retention of the row introduction and derivation edge is necessary if q is selected. Authority to publish that introduction remains separately unresolved.
