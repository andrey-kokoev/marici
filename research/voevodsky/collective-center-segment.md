# A segment from the future collective center

## Source declaration

Declare one logical arrow p→q before resolving its sender. The source p means “the normalized collective mode generated by the proton construction”; q is a terminal scalar receiver. It is not another complete four-state source, and it has no outgoing generators.

This is a deferred reference in the construction, not an assertion that an already formed spatial barycenter exists before the source is realized. The original proton construction must discharge the reference by supplying the collective mode and its decoder. It does so in this case.

The schedule is explicit: complete the proton return, resolve the collective amplitude at p, then send it unchanged to q. No face-specific phase correction is imposed on this scalar.

## Resolution from the actual source

The retained return is the rank-one projector

```text
N = U B,
U z = u z,
B x = u* x / (u* u),
B U = 1,
u* u = 80.
```

This factorization is reconstructed from the original generated triangle modes and compared to every entry of the retained N. It is also the collective-line factorization already used by the earlier source minimality checker.

For a coherent input U z:

```text
N(U z)=U z,
p=z,
q=z.
```

Thus a nonzero coherent proton and the receiver agree. The earlier three-channel character mismatch does not occur: there are no three independently corrected amplitudes here, only the one generated collective amplitude.

For arbitrary input x, the receiver receives Bx, while the source returns Nx. Its kernel component is not forwarded as an additional mode.

## Why the sender can be marked at the barycenter

The decoded collective amplitude is invariant under all twelve proper tetrahedral rotations. The checker verifies this on every input basis vector. The only spatial point fixed by all those rotations in the given tetrahedral realization is its barycenter, the origin.

Therefore, if we represent this invariant sender by an equivariant point marker, the barycenter is the unique choice. This supplies a symmetry-consistent spatial marker; it does not identify a complex scalar value with a spatial coordinate.

The receiver's location and segment length remain unspecified. A point beyond a chosen face can be drawn, but choosing that direction and distance is a separate spatial realization rule. No receiver tetrahedron is generated by the scalar transmission alone.

## Post-closure readout, not an arbitrary raw tap

After completion, every raw coordinate is u_j z. Since all u_j are nonzero, any one can decode z:

```text
z = (Nx)_j/u_j.
```

All 36 coordinate choices give the same functional B on the completed return. The canonical implementation chooses raw/AB/x, whose u_j is -2/3, so its normalization coefficient is -3/2.

This does not single out face ABC physically: the resulting functional is the same invariant B for every choice. The selected port is a compilation representative.

Reading that coordinate before closure is not equivalent. The checker supplies an input whose chosen initial coordinate is zero but whose completed collective amplitude is nonzero. The post-closure schedule is therefore part of the contract, not an optional description.

## Arrow accounting

Two typed implementations are kept distinct:

1. **Explicit center port:** add the normalization transfer from the completed source coordinate to p, then the identity segment p→q. Total retained coefficient support: **1838**.
2. **Proved center-coordinate alias:** substitute the known normalization into the segment's coefficient and omit the separate p storage port. Add one transfer to q. Total support: **1837**.

Both give exactly the same selected receiver output Bx, but they have different typed intermediate records. The second count is not obtained by merely wishing to add one to 1836: the alias is justified by the exact post-closure identity.

The original 1836-arrow subsystem and return certificate are unchanged. In the explicit implementation, deleting either new transfer destroys the typed receiver delivery. In the alias implementation, deleting the one transfer does the same. The receiver creates no new closed traversal.

These counts belong to the stated implementations. Choosing a representation because its number resembles a mass would not establish an energy law, and a specification requiring the explicit p record cannot silently use the alias count instead.
