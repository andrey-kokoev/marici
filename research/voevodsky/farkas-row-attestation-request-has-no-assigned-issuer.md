# Farkas row-attestation request has no assigned issuer

An exact INPUT packet for the fixed unit-square Farkas source is now frozen at `results/row-attestation-request.json`. It carries ordered primitive row normals/bounds, dimension, source ID, canonical SHA-256 digest `303476e7091ac755f3ef64ef2183e080f99e65c6d923c2ce0e2b2938dbf5c5c0`, requester, requested capability scope, mathematical checker locations, and the minimum owner evidence required: authorized issuer identity, independently bound manifest, source event, live generation and revocation route. Both `requested_owner` and `owner_event_id` are deliberately null. Fresh `check_row_attestation_request.py` checks digest mutation refusal and rejects self-declared owner/event fields as insufficient.

This is NOT a grant or a request sent to an invented owner. The fixed A/B vault belongs to a different source/history contract, and no admitted Farkas-row attestation issuer was found in the inspected evidence. A locally supplied digest identifies bytes but not who adopted them. Thus future protected use remains refused, while the independent Farkas arithmetic remains mathematically checked. Owner assignment and any actual handoff require an independently admitted recipient, not an invented actor label or a private `_admit` call.

The request-design leaf can close without parking the programme on a reply. A separate executable successor can test a concrete mathematical source-manifest change (e.g. upper bound 1->2) against archived proof packets and derived thin records, determine which portions must invalidate or be reverified, and keep source-owner admission separate. Analytic S,A,R,C,G roles remain deferred.
