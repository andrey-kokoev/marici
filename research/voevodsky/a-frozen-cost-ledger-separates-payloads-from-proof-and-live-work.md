# Frozen cost ledger separates payloads from proof and live work

The exact single-migration workload has two independently verified provider sessions, one public update `u<=3/4`, five reported full-domain lift comparisons, stale-provider refusal and fresh archived re-exposure. An owner-local ledger checker reads both independently recorded workload results, verifies the same migration binding and byte receipts, hashes shared source files, and extracts the first canonical owning migration proof packet from the existing compressed artifact. Fresh `python research/voevodsky/checkers/check_scoped_cost_ledger.py` passed.

The two receipt-field sums are 1,921 and 1,917 canonical payload bytes; their arithmetic subtotal is 3,838 bytes across two reported generations. The separately serialized owning proof case is 7,580 bytes. These are **not additive total retained information**: descriptors and proof dependencies overlap, shared source files have different retention horizons, and old heads, Python objects and full proof archives are unmeasured. The ledger reports byte count and hash per selected shared source file, not a measured runtime memory bill. Process-local handle generations are observed but token/object overhead unavailable; verification time and memory are unavailable. No external fine-rebase owner grant is consumed by this public-only operation. Redundant-refinement growth was not exercised.

No numerical upper bound on complete heap, total work or future archive/history growth follows from these local payloads. The exact missing accounts are part of the result, not silently zeroed.
