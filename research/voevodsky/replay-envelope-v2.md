# Replay envelope v2

Offline replay now requires the v2 schema identifier, an exact Boolean completion claim, ordered output roots with matching Boolean/scan type tags, and explicit provenance_status=unverified-constructor. Every observation root must actually be an OUT agent. Completed terminal leaves must match their declared tag, rather than accepting any result kind. Replay results retain the unverified provenance classification; a caller cannot label it verified through this field.

Fresh tests reject nine tampered traces, including wrong schema, mismatched observation type, truthy non-Boolean completion, unsupported provenance and a stronger false-completion case: truncate one step and recompute the correct truncated graph digest. That prefix is accepted when declared partial but rejected when completion is claimed. Thus hash agreement alone does not bypass terminal component validation. The70-step example still replays in a separate interpreter without production reducer modules. The refreshed25-suite closure passes.

This is version/tag/type hardening, not a full hostile-JSON parser: nested malformed shapes can still raise low-level errors and input byte/step-count limits are not imposed. Output metadata and the initial graph remain supplied by the trace, not independently tied to a source program. Hashes check consistency, not authenticity. A partial trace need not prove eventual termination from an arbitrary supplied initial graph.

Next central trust gap is initial compilation provenance. Specify and implement an independent structural recognizer for constructor-generated initial mixed-program nets against normalized input/program declarations, checking roots, ordered gates, unary operands, literal chains and no extra nodes. Recognition should not execute the production compiler or infer source declarations solely from the graph. This can bind replay to a declared programme without claiming authenticated authorship or allocator recovery.
