## The boundary adapter is explicit

The memory operator acts on a represented space W=R^2. The comparison map has endpoints A->B. Declare invertible identifications

    e_A:A->W,
    e_B:B->W.

For the interrogated operator D_W, the comparison reference is

    d_AB=e_B^-1 D_W e_A.

The implementation retains the boundary object names, W's identifier, both identification matrices and their provenance. It rejects missing provenance, wrong object roles, singular maps or a d_AB/inverse that does not equal the pinned reference/return.

For the supplied identity identifications and explicit two-unit source preparation, d_AB=2I and its inverse is I/2. The implementation does NOT choose a new input amplitude or rescale d_AB to force that result.

A common passive change of W coordinates leaves this scalar reference unchanged when both boundary identifications transform consistently. This is a coordinate control, not a physical gauge claim or general non-scalar coordinate theorem.

## Lifecycle and rejection controls

Stored-after-one-step and delayed-after-two-step references have equal matrices but different retained mode/depth/history. Both bind, with that difference retained.

After the third step the resource returns to the carrier and the active bank reference is zero. Binding that depleted bank as if it still contained the fixed reference is rejected.

Additional controls reject:

- a one-unit preparation instead of the declared two-unit resource;
- a changed one-sided boundary identification that changes d_AB;
- missing boundary provenance;
- replacing comparison A,B object roles with a carrier-port role.

Equal operator values therefore do not erase source history, and caller-supplied boundary data cannot silently change the pinned reference.
