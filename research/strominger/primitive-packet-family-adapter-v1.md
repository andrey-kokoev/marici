# Primitive packet family adapter v1: a checked supplied-family binding

## Result

`research/strominger/agda/PrimitivePacketFamilyAdapter.agda` now binds the proposed packet account to actual existing whole-package constructors for one precisely scoped class: SUPPLIED families of complete packages and supplied pointwise witnessed equivalences. A fresh safe Cubical Agda closure passes.

This is an adapter to existing Pi-congruence/reification theorems, not a new discovery of those operations. It does not generate the family, choose comparisons, or implement the full proposed phase cycle. In particular it does not solve the137-leaf generation schedule.

## Actual ports and payload

Inputs are an index type I, complete families F,G:I->Complete, equivalences e_i between their interpreted types, and actual paths

    p_i : e_i(value(F_i)) = value(G_i).

The active family ports are i:I; complete input packages, their expressions and p_i are retained, not replaced by scalar values. No restriction to a finite nonempty I is silently imposed.

The source and target assemblies are the EXISTING Pi-package(I,F) and Pi-package(I,G). Their interpreted payload types are dependent products of the component value types. The actual payload action is

    move(x)(i) = e_i(x(i)).

The comparison square is funExt(p). It compares moving the supplied source assembly with the supplied target assembly. `square-at` proves evaluation of this square at each port recovers EXACTLY p_i.

This provides a concrete port-and-payload interface rather than calling an arbitrary relation witness a transport. It is an equivalence-family specialization. It does not yet instantiate the general Layer3 history executor over a new WG or identify its action with every source-relation attachment.

## Retained operations and verified declarations

| Packet aspect | Existing construction used | Adapter theorem |
|---|---|---|
| unary comparison | identity-comparison(source) | stable-retained at terminal |
| family access | retained Pi-package input family | source-family-retained, target-family-retained |
| many-input assembly | Pi-package(I,F), Pi-package(I,G) | exact family recovery |
| family reconciliation | Congruence.all-comparisons | witness-retained recovers p_i |
| comparison of assemblies | Congruence.Pi-comparison | joint-comparisons-retained |
| payload action | pointwise e_i | square and square-at |
| terminal construction as object | remember(stable,reconciled), then reify | next-input-recovers-terminal |
| subsequent whole-package use | Pi-whole of the terminal packet | reused-entry |

The unilateral term `stable` is reflexive on the supplied source, not a test of stability relative to a separately supplied prior phase. Family access exposes already-supplied continuations; it does not discover which continuations are admissible. Thus this table is a partial binding of the proposed phase description, not a proof that all four stages have been generated by one selected law.

The output is a complete comparison package. No destructive quotient is taken. Reification increases the universe level explicitly. Subsequent reuse retains the exact terminal package at every supplied port; repeating that package is not independent operand generation.

## What the diagonal does here

The operation does not equate many:many with many:1. It compares two assemblies using a whole family of component comparisons. The diagonal's extra data is the family of actual witnesses p, preserved in `all-comparisons` as well as used in the assembled comparison. No switch to the prior Gray phase order is required to state this square.

This supplies a concrete comparison of family reconciliation and assembly. It does not yet identify the operator's expansion-to-synthesis chronological transition or its terminal-to-next-phase law with this square. That final identification needs a source-selected family and schedule, not an additional generic Pi-congruence proof.

## Remaining decisions, now explicit

- Which source-generated F and G represent the intended primitive packet's continuations?
- Which supplied/constructed e and p express its admitted comparisons, particularly if transitions are noninvertible?
- What is the comparison to the previous phase rather than a reflexive starting certificate?
- How is the terminal comparison promoted into the next phase with its retained source actions and attachments?

Do not assign id/Q2/Q3/Q4 or the137 count from the existence of these interfaces. The next research must bind actual source families, not add another generic packet wrapper.
