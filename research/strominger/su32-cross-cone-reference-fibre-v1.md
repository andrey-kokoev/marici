# One cross-cone reference attachment, not 224 independent laws

## Type classification

The 224 contacts in the previous edge-five audit do not directly join the two old comparison/reconciliation port types. On the downstream side, the referenced P/E cell is named by a **record field** inside a channel packet. Its value domain in `channelOperand` is opaque JSON. On the upstream side, the value is a validated comparison packet with occurrence anchor, three referenced records and two retained children.

These exposed types are not equal. The downstream API accepts `false`; no upstream comparison packet is `false`. Re-rooting or reversing an arc does not turn one type into the other.

However, every full comparison packet is admissible JSON. A common attachment is available without computing a new payload value.

## The uniform refinement

For an upstream occurrence A and comparison cell c, let C(A,c) be its valid full comparison-packet type. Refine the downstream reference-value fibre to the image of

\[
C(A,c)\hookrightarrow \mathrm{JSON}.
\]

The inclusion carries the entire packet literally. It does not extract a header, alter a value, or wrap the packet in a new envelope. The consumer's outer occurrence anchor remains its own; the original producer anchor and histories remain inside the payload.

`su32-cross-cone-reference-fibre.mjs` implements this one rule parametrically. `refineReference` validates the producer occurrence and cell. `attachReference` invokes the unchanged downstream `channelOperand`. `splitAttachment` recovers the upstream comparison, its operands and the other downstream reference value, then replays both original constructors.

This is a **candidate refinement**, not evidence that the full native fibration selects it. Given the refinement and literal-content preservation, no separate transformation is chosen at each contact.

## Cross-cone Segal comparison

The two operation vertices are now different from the previous within-cone fragment:

```
upstream operands → compareAt → full comparison packet
                                      ↓
other reference value ─────────→ channelOperand → downstream channel packet
```

Composition matches the complete upstream result with the refined reference value. The whole composite is obtained from the matching local rows, and restriction recovers those rows from the retained downstream packet. Both reconstruction directions preserve history.

The complete contextual attachment family and prepared producer points are built before evaluating any local reader. This does not construct the whole physical state by progressively extending readers.

Fresh finite checks cover:

- all **224 contacts**, with **448 actual shared-face reference appearances**;
- all sixteen producer/consumer sign-binding pairs;
- two null/structured payload preparations;
- **14,336 cross-cone reconstruction squares**;
- **7,168 checks** that both downstream appearances retain the same producer point.

The prepared bank contains 1,088 contextual source points. Repeated serialized appearances are not new independently prepared contents.

At each tested appearance, the unrestricted downstream API accepts a scalar, a history-free header, and a wrapped packet. The refined bridge rejects all three. Recoverability through a wrapper is not the same requirement as preserving the literal incoming content.

## Same location does not mean the same operation profile

There are **56 same-cell pairs of producer contexts** in the tested family. The audit exhausts those pairs rather than selecting one representative.

All 56 have different boundary profiles, including their actual record-reference support and input packet support. None is a same-profile pair distinguished only by its occurrence name. Therefore these are **not automatic equality obligations** in a cyclic operad. Forcing their outputs to agree merely because they occupy the same cell would discard typed structure.

A payload from the wrong producer context can still be accepted as generic JSON downstream. The refined fibre correctly refuses it. A stronger global theory may relate these contexts, but that relation must be typed and supplied; it is not inferred from location.

## Audit of the existing global wiring

The actual `sulfur-32-process.mjs` imports `sulfur-32-wiring.mjs`. That model exposes an edge-three candidate periodic fibration with 48 grouped cell fibres and 64 coordinate-axis wires, using the explicit period lattice generated by `1-4e_i`.

The checker freshly confirms that its grouping/restoration operations retain all 64 supplied payload rows in both presentations. Those exports do not bind the coordinate-axis wire identities to the context-indexed record fields tested here. Its periodic closure has not been imported into edge-five.

This preserves the distinction between a specified global wire fibration and the occurrence-level operation fragment. A common shape or a successful local inclusion does not establish their identification.

## Disposition

The earlier list of 224 contacts has been reduced to **one uniform, retained-content refinement and attachment** with checked instances. The common cross-cone two-vertex test passes. The same-cell profile audit also removes 56 unjustified equality demands.

Still required: identify this refinement with the globally specified content-bearing fibration and formulate its higher compatibility at fixed typed profiles. No arbitrary-tree cyclic operad, native eighty-fibre payload assignment, or physical inverse dynamics is claimed.
